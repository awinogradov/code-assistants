## [7.1.1](https://github.com/awinogradov/code-assistants/compare/autopilot@v7.1.0...autopilot@v7.1.1) (2026-08-24)

## Release Notes

The `pr-review` skill now owns its follow-up scoping logic directly, so review rounds stay correctly anchored even when history is rewritten or inline threads generate extra activity.

## 🐛 Bug Fixes

### Smarter Follow-Up Review Scoping

Previously, the logic that decided *how much* of a PR to re-review on a follow-up pass lived outside the `pr-review` skill itself, which made it easy for that policy to get applied inconsistently. That logic now lives inside the skill where it belongs.

In practice, this means the skill correctly handles three situations that previously could go wrong:

- **Inline thread replies** no longer reset the review scope — only a new substantive review (one that actually looks at code) counts as the anchor point for what to re-review next time.
- **Fast-forward pushes** are reviewed efficiently: only the commits added since the last real review are examined, not the whole PR again.
- **Rewritten history** (e.g. a force-push after a rebase) triggers a full re-review, since the commit chain has changed in a way that makes incremental comparison unreliable.

Published reviews are now bound to the specific commit they reviewed via `commit_id`, which is what makes the above anchoring reliable across history changes.

### No More Duplicate "Approval Skipped" Messages

When the skill determined that a PR didn't need a new review pass, it was emitting the approval-skip message twice. That duplicate output is now gone — the skip is reported exactly once.
