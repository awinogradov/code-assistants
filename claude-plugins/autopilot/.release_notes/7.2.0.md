## [7.2.0](https://github.com/awinogradov/code-assistants/compare/autopilot@v7.1.2...autopilot@v7.2.0) (2026-08-27)

## Release Notes

Autopilot can now be installed as a version-pinned npm package, giving teams a dependency-managed distribution path with full lockfile integrity.

## ✨ What's New

### npm Package Distribution for Autopilot

Autopilot is now published to npm as `@code-assistants/autopilot`, making it a first-class dependency you can pin and manage alongside the rest of your project's packages. Instead of tracking a plugin version and a source commit SHA separately, you pin one exact version in `package.json` and your lockfile records the resolved artifact with registry integrity. Dependabot and Renovate can then propose upgrades through their normal dependency workflows.

The npm package is itself a valid local Claude Code marketplace — it ships its own `marketplace.json` — so once installed into `node_modules`, you register and install it locally without any writes to Claude's internal plugin cache:

```bash
npm install --save-exact @code-assistants/autopilot

/plugin marketplace add ./node_modules/@code-assistants/autopilot
/plugin install autopilot@code-assistants-autopilot
```

The existing GitHub-direct and `/plugin marketplace add` installation paths remain fully supported and unchanged.

## ⚙️ Configuration Required

### npm Token Required for Publishing

The stock release-publish workflow authenticates to npm with an `NPM_TOKEN` repository secret — its `pull_request_target` trigger cannot obtain GitHub OIDC tokens, so trusted publishing does not engage there. If your environment or fork publishes releases, set `NPM_TOKEN`; the underlying release-action still supports OIDC trusted publishing when invoked from a workflow trigger that can mint OIDC tokens. No change is needed for teams that only consume the package.

## ⚠️ Breaking Changes

### Version Consistency Now Enforced Across All Manifests

Repository validation now fails if the version number drifts between the npm `package.json`, the Claude plugin manifest (`.claude-plugin/plugin.json`), and the release manifest. If you maintain a fork or a custom packaging setup that sets these versions independently, they must be kept in sync or the build will reject the release. Align all three manifest versions before cutting a release.
