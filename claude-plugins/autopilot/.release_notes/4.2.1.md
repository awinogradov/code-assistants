## [4.2.1](https://github.com/awinogradov/code-assistants/compare/autopilot@v4.2.0...autopilot@v4.2.1) (2026-08-04)

## Release Notes

Context rules for distributed agents now resolve tooling versions dynamically from each consumer repository instead of assuming project-specific compiler versions.

## 🐛 Bug Fixes

### Accurate Tooling Context in Distributed Agent Rules

When the autopilot plugin generates or distributes context rules to sub-agents, those rules were incorrectly hard-coding TypeScript 6 as the assumed compiler version and referencing Graphify CLI commands (`--graph`, `affected`) that no longer exist in the installed Graphify skill contract. This caused agents operating in consumer repositories to work from a false picture of the project's toolchain — most visibly breaking `wefortis/fortune-os` where the generated `NodeJS+React+Tailwind` rule was rolling the project back to a non-existent TypeScript version and issuing invalid Graphify commands.

The rules now resolve TypeScript, React, and Vite versions and compiler roles directly from each consumer repository at runtime. Graphify context acquisition has been restored to its query-first pattern across all four stack rules, the stale `--graph` and `affected` command forms have been removed from the shared context contract, and `GRAPH_REPORT.md` is treated as a broad architecture and fallback source rather than a mandatory first read.
