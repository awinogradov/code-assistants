## [4.1.0](https://github.com/awinogradov/code-assistants/compare/autopilot@v4.0.0...autopilot@v4.1.0) (2026-08-03)

## Release Notes

Context gathering is smarter in 4.1.0 — skills now prefer a committed graphify knowledge graph over repomix when scanning your codebase, and planning context can now trace files and commits back to the agent sessions that created them.

## ✨ What's New

### Graphify Knowledge Graph Takes Priority for Codebase Context

Autopilot skills now follow a clear preference order when gathering codebase context: a committed graphify knowledge graph is checked first, falling back to the repomix pack if one isn't available, and then to plain repository tools as a last resort. If your repo has a graphify graph committed, agents will use it automatically — no configuration needed. This produces richer, more structured codebase understanding compared to a flat repomix pack, which means skills like `pr:review` and `expert-review` have better raw material to work from.

### Session History Wired Into Planning Context

When [Entire](https://github.com/awinogradov/code-assistants) is available in your environment, the Context Map produced during planning now links each task's relevant files and commits to the agent sessions that originally produced them. This closes a visibility gap where prior agent work — what was decided, what was changed — wasn't surfaced when picking up a task. Agents can now see not just *what* exists in the codebase, but *which session* put it there and why.
