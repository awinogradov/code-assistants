## [5.1.0](https://github.com/awinogradov/code-assistants/compare/autopilot@v5.0.0...autopilot@v5.1.0) (2026-08-11)

## Release Notes

The code review skill now reads your project's own `CODE_REVIEW.md` as the primary rules source, letting teams define and enforce their own standards without touching plugin internals.

## ✨ What's New

### Project-Defined Code Review Rules

Teams can now place a `CODE_REVIEW.md` file at the root of their repository to serve as the primary source of code review rules. When this file is present, the review skill uses it instead of falling back to the built-in docs, RFC, and principles discovery. Review findings reference your own rule IDs and severity levels, linked directly to the relevant anchors in your `CODE_REVIEW.md` — so review comments point your team at your own standards, not generic plugin guidance.

The same precedence applies during plan generation: when the skill digests review standards as part of planning, it picks up `CODE_REVIEW.md` first.

If no `CODE_REVIEW.md` exists at the repo root, behaviour is unchanged — the plugin falls back to its built-in discovery as before.
