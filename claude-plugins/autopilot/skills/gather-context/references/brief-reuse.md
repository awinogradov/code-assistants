# Reuse a validated brief

A valid base is necessary, not proof that every claim applies to this task. Consume Architecture map, Data flow, Conventions and standards, Key types, and Test and verify only after checking the evidence below. Ignore the brief's volatile sections and session-scoped snapshot handles; acquire fresh Git state and a current source handle.

- Read the optional `brief.sources.json` beside the brief. It follows [explore's refresh contract](../../explore/references/selective-refresh.md). Verify its `base` matches the brief and its `briefBlob` matches `git hash-object -- <brief-path>` before trusting dependencies. Missing, incomplete, or mismatched metadata makes the brief navigation-only: retrieve task-relevant code and standards before using its claims.
- Compare every recorded source `blob` with `git hash-object -- <path>` in this checkout, even when Git status is clean; missing files or hash differences invalidate their dependent claims. This detects a brief written from dirty content and later copied into a clean checkout. Also compare `base..HEAD`, staged and unstaged changes, and untracked paths with the recorded dependencies and discovery roots. Read overlapping paths from the working tree with the source contract's working-tree fallback reason. A structural change or unknown dependency invalidates the affected claims; do not reuse them merely because the base matches.
- A broad brief is not a complete task standards digest. Retain its applicable clauses and overflow; retrieve task-specific standards it omitted or whose source changed. Skip the standards agent only when coverage for this task is established from complete source evidence. Otherwise request a narrowed digest with already captured clauses.
- Carry the usable stable sections into the Context Map, supplemented by current task evidence. Never replace known conventions with `none` because their digest was skipped. Preserve conditions, exceptions, source paths, dropped candidates, overflow, and errors.
